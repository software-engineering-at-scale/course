# Contributing

Software Engineering at Scale is beginning with a syllabus and a question: what experiences would better prepare a graduating software engineer to work responsibly in a mature organization that uses AI throughout development?

Contributions are welcome from educators, students, software engineers, product leaders, security practitioners, compliance professionals, site reliability engineers, and maintainers of open-source projects.

## Useful contribution areas

- Critique or clarify a learning objective
- Propose a realistic two-week exercise
- Contribute an anonymized production failure that can be turned into a teaching scenario
- Recommend a suitable open-source reference application
- Design a regression, dependency, security, performance, or operational challenge
- Improve the assessment model
- Suggest a responsible way to evaluate individual learning in AI-assisted team work
- Add instructor guidance, student materials, or adoption notes
- Identify where the proposed course duplicates or can learn from existing university courses

## Design principles

Contributions should preserve these principles:

1. AI use is required, not hidden or merely tolerated.
2. Students remain responsible for the systems they change.
3. Requirements definition and acceptance are part of engineering.
4. Exercises should teach why a practice exists, not just require a tool or checklist.
5. Evidence matters more than claims of completion.
6. The system must evolve across the semester rather than being discarded after each assignment.
7. Retrospectives should change the team’s Definition of Done.
8. The course should prepare students for continued learning, not imply that one semester creates an expert.

## Current stage

The project is still defining its initial curriculum, governance, licenses, and reference application. Early contributions should focus on sharpening the educational design before expanding implementation.
